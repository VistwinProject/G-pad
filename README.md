# 住戶端 Pad — 逃生指引

火災黃金30秒 / 雲端宅邸的**住戶端**。放在平板上，同步顯示主展示端的警報狀態與 AI 建議出口。

> 主展示端（大螢幕看板）在 [VistwinProject/G-main](https://github.com/VistwinProject/G-main)。
> 這兩個 repo 的歷史是同一份，拆開之前的 commit 兩邊都留著。

狀態主要由主展示端透過 WebSocket 推過來。

⚠️ **但有兩個手動操作會反過來控制大螢幕**（以前 Pad 是「只負責顯示」）：

| 在 Pad 上做什麼 | 兩邊會變成 |
| --- | --- |
| 待機頁**點一下** | Pad 進火災警報，大螢幕跟著切到「火災黃金30秒」 |
| 警報頁**往上滑**（超過 40px） | Pad 進雲端宅邸 App，大螢幕跟著切到首頁 |
| App 頁按**逃生指引** | 大螢幕**隨機挑一條**動線開始跑，兩邊一起切到「前往 X 出口」 |
| 出口頁按 **▶**（展示） | 大螢幕**重跑目前這一條**動線 |
| 出口頁按 **⇄**（切換） | 大螢幕**換一條**動線（避開剛剛那條） |

▶ 和 ⇄ 在出口頁**最下面那張統計卡的右邊**（`剩餘距離 | 已避開火源 | ▶ ⇄`）。
放那裡不只是為了好按 —— 那一頁沒有多的垂直空間讓它自己排一列，詳見 UI-SPEC。

後面那三顆走的路不一樣：前兩列是 Pad **自己換頁再通知**大螢幕（`drive()`），
後三列是 Pad **只送指令**、畫面等大螢幕回話（`command()`）。

⚠️ 為什麼不讓 Pad 自己挑動線：**挑第幾條、跑幾秒只有大螢幕算得出來**
   （動線長度在它的 `tower` 模型裡）。Pad 先自己猜一條就會跟大螢幕跑不同的路線，
   小人的對時也就沒有意義了 —— 路線的決定權只能有一個地方。
   所以這三顆**故意不做本機的樂觀渲染**，沒連上就只跳提示、什麼都不換。

⚠️ 指令帶一個不重複的 `cmdId`，大螢幕**只在序號變了的時候**才執行。
   轉播站是把最後一份狀態存起來、誰連上就補送一份，指令會一直留在共用狀態裡；
   不看序號的話大螢幕每次重新整理都會自己再跑一次動線。
   而且大螢幕**第一次**收到狀態只記住序號、不執行（那份是補送的歷史，不是剛剛按的）。

⚠️ 送出後按鈕會鎖 900ms。大螢幕收到之後會先黑一下再起跑，那段期間畫面沒反應，
   不鎖很容易連按好幾下、送出一串指令。

送出去的是**完整一組欄位**，不是只送 scene —— 轉播站是 `{...state, ...msg}` 併起來的，
只送 scene 的話舊的 `exit` / `phase` 會留在共用狀態裡（切到 aiRoute 而 exit 還是 A，
Pad 就會跑去顯示「前往 A 出口」而不是 App 那一頁）。

不會打回圈：主展示端的 `goto()` 開頭就 `id === current` 直接 return，而且轉播站不會把
訊息轉回給發送者本人。

### 「大螢幕沒有跟著動」先看這裡

⚠️ 這兩個操作**沒連上轉播站也照樣會換 Pad 自己的畫面**（`drive()` 會先送、再本機 render）。
   所以「Pad 有反應、大螢幕沒動」最常見的原因**不是程式壞了，是根本沒連上**。

而待機／警報／App 這三頁為了做成手機鎖屏的樣子，狀態列**刻意把「已連線」的文字藏起來**了
（見 `css/pad.css` 的 `.pad__link`），斷線只剩一個很小的訊號圖示在閃 —— 現場看不出來。
所以現在沒連上的時候操作會**在畫面下緣跳一行字**：

> **沒有連上大螢幕**
> 網址要帶 ?server=大螢幕IP:5280

看到這行就是去修網址（見下面「現場怎麼跑」），不用查程式。

沒跳那行字、Pad 也換了頁，但大螢幕還是不動的話，依序查：

| 查什麼 | 怎麼判斷 |
| --- | --- |
| **大螢幕那一頁是不是舊的** | 最常見。改過 G-main 的 `js/main.js` 之後那一頁要**強制重新整理**（Ctrl+F5）。舊版的 `main.js` 是「只送不收」，收到狀態根本不會換頁 |
| 大螢幕有沒有收到 | 開它的 Console，應該每次都印一行 `[sync] 收到狀態 scene=… → goto(…)`。**沒印**＝訊息沒到（查網路／埠號）；**印了但畫面沒換**＝下一列 |
| `goto()` 有沒有炸 | Console 會印 `[sync] 跟著 Pad 換頁失敗`。這台開不了 WebGL 時 `new Viewer()` 會讓模組初始化中斷，後面的 `current` 停在 TDZ —— 換頁就會失敗 |

## 現場怎麼跑

```
node server.mjs 5281        # 開機時會印出區域網路的網址
```

**同步的轉播站不在這邊**，在 G-main 的 `server.mjs`。所以平板的網址要指定主機：

```
http://<這台的 IP>:5281/?server=<跑 G-main 那台的 IP>:5280
```

⚠️ 這個位址**不會記起來** —— 請把帶參數的網址直接加成平板的書籤。
   故意不存 `localStorage`：記住一個舊的 IP，之後現場換網段時比每次貼網址更難查。

⚠️ **不要在這邊也開一個轉播站**。兩台各自跑一個的話就是兩座孤島，反而同步不到。
   現場只跑 G-main 那一台，這邊純粹是靜態檔。

⚠️ 兩台跑在同一部筆電上時記得**錯開埠號**（這邊預設 5281，G-main 是 5280）。

平板也可以直接開 G-main 那台的網址，就不用 `?server=` —— 前提是那台也放了這份頁面。
拆成兩個 repo 之後預設不是這樣，所以現場請照上面的網址走。

## 連上了沒

右上角有連線指示燈：

- **已連線** —— 綠點，正常
- **連線中…** —— 紅點閃爍。網址的 `?server=` 打錯、G-main 那台沒開、
  或兩台不在同一個 Wi-Fi，都會停在這個狀態

斷線會**自己重連**（1.5 秒一次），現場網路抖一下不用重整頁面。
而且 G-main 那台記著目前狀態、**一連上就先推一份**，所以平板晚開機、
重整、中途斷網回來，都會立刻對上大螢幕，不用請人在主控端再按一次。

⚠️ 重連的人是**去跟上轉播站**，不是把自己的狀態蓋上去 —— 兩邊都只送 `{type:'hello'}`。
   曾經有一版是「主展示端重連時把自己最後送出的狀態補送一次」，那在**單向**的時候沒問題，
   但同步變雙向之後就變成「誰後重連誰說話」：大螢幕網路抖一下重連，
   會把 Pad 剛剛切的頁蓋回去，現場看起來像畫面自己跳回去。
   轉播站存的那份才是兩邊共同的狀態。
   主展示端自己往前跑的頁也不會漏掉：它每次 `goto()` 都推一次，動畫進行中還有每秒的心跳。

## 四個狀態

主展示端換頁，這邊就換一個狀態（配色 `body[data-state]`、版面 `body[data-view]`）：

| 主展示端 | 送過來的場景 | 這邊顯示 | 色調 |
| --- | --- | --- | --- |
| 前言 | `intro` | **待機頁**：乾淨的鎖屏（時間／日期／系統名），不放通知 | 藍 |
| 火災黃金30秒 | `golden30` | **火災警報**：同一張鎖屏轉成紅色，跳一則「住宅火災警報」通知，**進場會震動** | 紅 |
| 逃生動線（待機） | `aiRoute` | **雲端宅邸 App**：從警報頁向上滑動帶出來的主畫面（主視覺那張圖可以上下滑） | 藍 |
| 逃生動線（跑動線） | `aiRoute` | **緊急疏散提示**：前往 X 出口 + 平面圖 + 會跑的小人 + 剩餘距離 | 藍 |
| 結語 | `outro` | 疏散完成／**已離開危險區域** | 綠 |

`aiRoute` 還分三種：

- **還沒開始跑動線** → 從警報頁**向上滑動**，帶出「雲端宅邸 App」的主畫面
  （那時候大螢幕也正停在首頁待機，語意剛好對上）。
  ⚠️ 這時候**不會報出口，平面圖和小人整個不畫** —— 主展示端根本還沒挑動線，
     報了就是假資訊，現場住戶照著走會出事。
- **跑動線中** → 「請前往 A／B 出口」＋平面圖上那條真的動線＋**跟著大螢幕跑的小人**＋剩餘公尺數
- **跑完（通關）** → 整頁轉綠、標題換成「已抵達 X 出口」、小人停在出口、剩餘距離歸零

### 小人怎麼跟大螢幕跑在一起

不是每一格都傳。主展示端在狀態裡多送一段「這個動畫什麼時候開始的、要跑幾秒」：

```
anim : { kind:'count'|'route', t0:<開始時的 Date.now()>, dur:<秒> }
now  : <送出當下的 Date.now()>
```

Pad 算 `已跑秒數 = now - t0`，之後自己往前推。倒數的秒數也走同一套。

⚠️ 一定要用 `now - t0`，**不能**用「Pad 現在的時間 - t0」—— `t0` 是大螢幕那台的時鐘，
   兩台的系統時間不會一樣。

⚠️ 動畫進行中主展示端**每秒補推一次**。轉播站只存最後一份狀態、有人連上就補送，
   不補推的話 Pad 晚開機／重連拿到的會是一份 `now` 很舊的狀態，進度就停在那一刻。

⚠️ 小人的位置跟大螢幕**完全一樣**：照含樓梯的全長換算，再夾在這一層的範圍內。
   俯視圖沒有垂直動線，所以只取「在這一層的那段時間」—— 小人照真實速度走，
   在大螢幕的人踏進樓梯間的同一刻抵達樓層出口（約全程的 41～59%），之後站在出口等。
   不要改成「整段跑完才到出口」，那樣大螢幕的人在下樓梯時，Pad 的人還在走廊上晃。

⚠️ 五條動線的平面圖**共用同一個裁切框**（整層樓）。不要改回照每條動線各裁一塊，
   那樣每條的比例尺都不一樣，換一條圖就忽大忽小。

⚠️ 改完主展示端的 `js/main.js` / `js/countdown.js` 之後，**大螢幕那一頁要重新整理**。
   舊的頁面不會送 `anim`，Pad 收不到時間資訊，小人就會一直站在起點不動。

⚠️ 這是**跨 repo 的約定**：主展示端那邊是 `js/main.js` 的 `anim`／`pushSync`／心跳，
   和 `js/countdown.js` 的 `onCycle`。改了兩邊都要動。

出口的規則跟主展示端右上角那塊狀態面板一樣：動線 1/2/3 走 A、4/5 走 B。

### 平面圖是真的

「前往 X 出口」那頁的迷你平面圖，底圖是**一層切平面那顆 BIM 模型的正射俯視投影**
（樓板／牆／核心筒／柱／樓梯／窗框六層），動線是主展示端 `models/routes-home.json`
那五條**同一份資料**（首頁真的在跑的那一份），剩餘距離是這一層那一段的長度（14.9～27.0m）。

兩邊都由 `tools/extract-plan.mjs` 壓成 `js/plan-data.js`（406 圈輪廓，約 28KB）。
**這個 repo 不放模型檔、不載 three.js** —— 平板不該為了一張小平面圖去下載 16MB 的模型。
模型或動線改了才需要重跑那支工具，平常不用（它讀的兩個來源都在主展示端那邊）。

底圖畫成**藍圖式的線稿**（藍色描邊、不填色，襯一層藍色漸層底）。動線分兩段：
**走過的畫實線**、**還沒走的畫虛線**，顏色是紅的（通關之後轉綠），小人是**白色**的
—— 小人正踩在紅線上，同色就看不到人了。

⚠️ 俯視圖是「只留朝上的面、消掉共用的邊、把剩下的邊接成輪廓」抽出來的，是精確的投影。
   **不要改用凸包** —— 樓板外框是凹的，凸包會把缺角補起來，圖上會多一條橫貫整層的假牆，
   門窗開口也會被封掉。

⚠️ 待機頁**刻意留白**，不放常駐的卡片或狀態磚 ——「平常空著、有事才跳一則通知」
   這個對比本身就是資訊。（舊版放過通知卡、三張狀態磚和天氣，都是寫死的假資料，已移除；
   現在待機頁上會動的只有時鐘和電量，兩個都是真的。）

## 之後要包成 App（Capacitor）

現在是**純網頁**：沒有 build step、沒有 node_modules、沒有伺服器端邏輯，
整個資料夾可以直接當 Capacitor 的 `webDir`。下面是已經先留好的接縫、
還沒做的事，以及哪些**非得等 macOS**。

### 已經備好的

- 全部靜態檔、全部相對路徑（`./css/…`、`./js/…`）—— App 用 `capacitor://` 開也找得到
- `server.mjs` 只是開發用的靜態伺服器，包成 App 之後用不到，不影響打包
- 「要連哪一台大螢幕」抽成一個接縫：`window.PAD_SERVER`（見下）
- 震動集中在 `js/pad.js` 的 **`haptic()` 一個函式** —— 換成原生 Haptics 只改那裡
- 版面已經吃 `viewport-fit=cover` + `env(safe-area-inset-*)`，瀏海和圓角不會切到字

### `window.PAD_SERVER`

純瀏覽器是用網址的 `?server=`。包成 App 之後**沒有網址可以帶參數**，
`location.host` 也只是 app 自己的位址，所以要在載入 `js/pad.js` **之前**先設好：

```html
<script>window.PAD_SERVER = '192.168.0.12:5280';</script>
<script type="module" src="./js/pad.js"></script>
```

（`<script type="module">` 是 deferred 的，所以前面那支普通 script 一定先跑。）
沒設就維持原本 `?server=` 的行為，兩種方式不衝突、也不用改 `js/sync.js` 以外的東西。

### 還沒做，但**都可以在 Windows 上做**

| 事情 | 為什麼要做 |
| --- | --- |
| 字型改成打包在本機 | 現在從 Google Fonts CDN 載。現場只有區域網路、或 App 離線時載不到，中文會掉成系統字型，版面會跑掉。（桌布已經是本機檔案了，不受影響） |
| Android 的 `ws://` 會被擋 | Capacitor 的 Android 預設用 `https://localhost` 開頁面，混合內容政策會擋掉 `ws://`。要在 `capacitor.config` 設 `androidScheme: 'http'`，或讓轉播站改走 `wss://` |
| App 裡要能設定大螢幕位址 | 現在靠網址參數。包成 App 之後沒有網址列，得有個設定畫面或設定檔。⚠️ 前面說明過「刻意不用 localStorage 記住 IP」的理由（怕記到舊網段），包成 App 之後這個取捨要重新想一次 |

### 要等 macOS 的（先不要碰）

- **iOS 的觸感回饋**：iOS 的 Safari / WKWebView **完全沒有** `navigator.vibrate`，
  要換成 Capacitor 的 Haptics 外掛。改的地方只有 `js/pad.js` 的 `haptic()` 一個函式。
- `npx cap add ios`、Xcode 簽章、跑實機 —— 這些都只能在 macOS 上做。

⚠️ 在那之前，**不要**為了 iOS 先把 `haptic()` 改成需要 Capacitor 執行期的寫法 ——
   純網頁版就跑不起來了。現在的寫法在沒有 Capacitor 的情況下是安全的（`?.` + try/catch）。

   那支是給 1920×1080 看板算的（取 vw/vh 較小者），平板直向時會算出很小的 rem。
   Pad 改用**版面盒子的寬度**為基準（不是 vmin —— 視窗變寬時 vmin 會跟著變大，
   但盒子被長寬比綁住沒變大，字就會撐爆版面）。色票還是共用，換主題色兩邊會一起變。

⚠️ 警報頁那則通知的**白色面板會慢慢呼吸**（明暗，2.6 秒一個來回）。
   ⚠️ 呼吸的是面板，**背景不要動**。而且是用 brightness 不是調透明度 ——
      透明度一降紅底就透上來，深色的字反而更難看清楚。

⚠️ 警報頁進場會**震動一次** —— 觸感回饋那種短促的三下（`[30,60,30,60,45]`），
   配上通知卡彈入 + 版面輕敲一下。**不要整片閃**，也不要做成警報器那種長嗡嗡 ——
   整片閃在平板上很吵，也容易讓人不舒服。震動只在**進入**警報頁那一次，
   不是每次收到狀態都震（主展示端每秒補推一次，每次都震會抖個不停）。
